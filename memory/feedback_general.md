Ask before running pip installs or file edits that could affect the app — user is cautious about breaking things.

**Why:** User rejected a pip install mid-session and asked "will this affect my app" before venv recreation.

**How to apply:** Always explain what a command will do and ask for confirmation before pip installs, venv changes, or large file rewrites.

---

User prefers concise explanations — doesn't want long multi-paragraph answers unless asking for full code.

**Why:** Observed throughout session; user asks short questions and expects short answers.

**How to apply:** Keep responses tight. Only write full code when explicitly asked ("show me the full code").

---

User likes to understand the "why" before approving changes — explain the root cause, then propose the fix.

**Why:** User asked "explain to me my error" before approving the upsert fix.

**How to apply:** When fixing bugs, briefly explain what's wrong before making the edit.
